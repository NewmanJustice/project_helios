## Summary
Implement the helios-portal: a vanilla HTML/CSS/JS static site gated behind a password (`helios2025` read from `config.js`), presenting eight narrative content sections with a fixed side-rail progress indicator and scroll-triggered CSS animations. The approach creates five files at the project root — `config.js`, `staticwebapp.config.json`, `style.css`, `index.html`, and `app.js` — ordered so that each file enables an incremental slice of the test suite to pass before the next file is added.

## Risks
- T-SA-7 selector check is a regex over JS source: the `querySelectorAll` call must not match `section-0` in its argument string — use a class-based or `[data-section]` selector scoped to content sections rather than a range selector that incidentally includes section-0.
- T-PC-3 is a hard `includes('To be defined')` match on the fourth `<li>` in the roadmap — any additional wrapper elements before it (e.g. a heading `<li>`) would shift the index and cause a false failure; the four step `<li>` elements must be direct/first-level children of a single list with no preceding list items.
- T-DS-6 requires `font-display: swap` inside the CSS file itself (inside a `@font-face` block), not only as an attribute on a `<link>` tag in HTML, because the test reads `style.css` directly.
- T-PI-2 regex matches a CSS rule block where the selector contains "progress", "sidebar", or "rail" AND the block body contains `position: fixed` — the selector and opening brace must appear on the same logical line/run without intervening `}` characters for the `[^{]*\{[^}]*position\s*:\s*fixed` pattern to succeed.
